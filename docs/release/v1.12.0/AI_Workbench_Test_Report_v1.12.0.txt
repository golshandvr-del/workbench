Root-cause findings addressed
----------------------------
- Prompt-level: earlier prompt branches used inconsistent/partly conflicting plan schemas. All prompt-stage paths now share the canonical `workbench-plan-v2` context-plan contract, which explicitly overrides implementation JSON/ZIP/Gemini transport when existing source context is missing.
- Parser/importer: the old validator allowed only canonical `requested_*` fields while the model response used legacy `requests`, `manual_attachments`, and metadata keys. A constrained migration adapter now accepts known aliases and normalizes known modes before strict validation.
- Error observability: the pasted JSON and quoted error named different keys (`requests`/`manual_attachments` versus `request`/`manual_attechent`). The previous validator echoed keys from the input object, so those texts likely came from different text or an error transcription typo. Diagnostics now include the current raw-response SHA-256 and actual parsed top-level keys. The diagnostic journal stores only structured metadata and the hash, not raw response text.
- Workflow/history: a rejected `Import context plan` attempt used to return before saving the failed reply. It is now attached to the active prompt-history step as a rejected response attempt when persistence succeeds, with an execution-journal event recording the fingerprint and validation error.
- Type safety: malformed JSON protocol/status/action/scope/list types now produce Workbench validation errors rather than uncaught internal type exceptions.

Important interpretation
-----------------------
In the user sample, the prompt inventory showed the file tree but no source file contents. The model was right to ask for the existing source files rather than fabricate an installer rewrite. The failure was that Workbench rejected the legitimate legacy plan structure. After importing the plan, the user must review the selected paths, generate the follow-up implementation prompt (which includes file contents under Workbench's normal safety/size checks), and manually send that prompt to the same model chat. No source implementation is claimed by this release report.

Platform limits
---------------
All tests ran in the available Linux/Python environment; GUI flows used Xvfb. The installer wrapper and embedded ZIP were verified at the byte/string/ZIP level, and the extracted payload's Python suite passed. A native Windows 10/11 double-click install/update was not executed in this environment and remains unverified. The installer must still be smoke-tested on a target Windows machine.
