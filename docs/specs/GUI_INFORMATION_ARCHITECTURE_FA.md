# معماری اطلاعات و جریان‌های کار GUI (GUI roadmap، مرحلهٔ 2)

**تاریخ:** 2026-10-19 · **نسخهٔ سند:** 1.0 · **ورودی:** `GUI_AUDIT_FA.md`، `GUI_RESEARCH_FA.md`

## ۱. مدل ذهنی

«انتخاب پروژه → فهم وضعیت → انتخاب کار → انجام قدم بعدی → بازبینی نتیجه». Team و Timeline پشتیبان این گردش‌اند، نه اپ‌های جدا.

## ۲. مقصدهای اصلی (ترتیب Sidebar، `Alt+1…7`)

کلیدهای داخلی (`SECTIONS` در `workspace/controller.py`) برای سازگاری `ui.json` حفظ می‌شوند؛ فقط ترتیب و برچسب تغییر می‌کند.

| # | کلید | برچسب en / fa | پرسش کاربر | صاحب این قابلیت‌ها | دیگر اینجا نیست |
|---|---|---|---|---|---|
| 1 | `overview` | Overview / نمای کلی | الان کجام و قدم بعدی چیست؟ | قدم بعدی (تنها Primary)، Needs Attention، پیشرفت، فعالیت اخیر انسانی | شمارش خام همهٔ وضعیت‌ها (به جزئیات پیشرفت رفت) |
| 2 | `tasks` | Tasks / وظایف | چه کاری باید انجام/بررسی/اصلاح کنم؟ | فهرست Task با فیلتر، پنل «پرامپت و پاسخ» با وضعیت ارسال، Repair، درخواست تغییر | — |
| 3 | `team` | Team / تیم | چه نقش‌ها و چت‌هایی دارم؟ | Agentها + آمادگی، پروفایل‌های اکانت، برنامه‌ریزی تیم، بازبینی Proposal (در زیربخش‌های جدا) | — |
| 4 | `timeline` | Timeline / تاریخچه | چه رخ داده؟ | رویدادها با جملهٔ انسانی، فیلتر، Lane | Milestone/Version (به Deliveries رفت، IA-3) |

| 6 | `versions` | Deliveries / تحویل‌ها | چه چیزی Build/منتشر شده و شاهدش چیست؟ | Milestoneها، Versionها با سطح شاهد (proposed/local/tagged/released + منبع)، Build Center و Sync & Build | — |
| 7 | `settings` | Settings / تنظیمات | ترجیحات کجاست؟ | زبان، تم، حالت Simple/Advanced، میان‌برها، Companion، پنجرهٔ کلاسیک | — |

**Project Bar:** ☰ · نام پروژه · هدف کوتاه · وضعیت محلی/GitHub · ⓘ (Inspector). Mode/Language/Theme از Project Bar به Settings منتقل می‌شوند (IA-7). تغییر آن‌ها فقط `ui.json` را تغییر می‌دهد.

**Status line:** وضعیت کلی و نتیجهٔ آخرین اقدام (کم‌مزاحمت). پیام‌هایی که برداشت کاربر را عوض می‌کنند (هنوز ارسال نشده، پاسخ قدیمی، خطا) در **Banner درون‌صفحه** نمایش داده می‌شوند و در Status line هم تکرار می‌شوند (CC-5).

## ۳. سطح‌بندی اطلاعات هر عنصر

| عنصر | لازم در لحظه | با انتخاب (Inspector) | پیشرفته (Advanced) |
|---|---|---|---|
| Task | شناسه، عنوان، وضعیت انسانی + نماد، گام گردش کار، Agent | هدف، معیار Done، گام + دلیل، اکانت/چت، اقدام‌های مجاز | Attempt ID، Revision، Evidence |
| Agent | نام، نقش، اکانت، چت، Taskهای باز، گام فعلی، «نیاز به شما»، آماده؟ | آمادگی + علت، Taskهای باز، اقدام Binding | برچسب مدل قدیمی |
| رویداد | زمان محلی، جملهٔ انسانی، مرجع، منبع | جزئیات refs، منبع زمان، اقدام «باز کردن Task» | `event_type` خام، revision |
| Version | شناسه، عنوان، وضعیت + **منبع شاهد** | commit/tag/release URL، Taskها | — |
| Context Request | Task، فایل/بازهٔ خطوط، علت، «آماده» یا «ارسال‌نشده» | متن بسته | — |

## ۴. واژه‌نامهٔ UI

قاعده: شناسه‌ها (`TASK-0001`، `HO-0002`، `ACC-0001`) و نام‌های محصول (Agent، Task، Prompt) بدون ترجمه می‌مانند و در متن فارسی با جهت LTR جاسازی می‌شوند. اولین ظهور اصطلاح فنی در Inspector یک توضیح کوتاه دارد.

| en | fa | توضیح کوتاه (Inspector/Tooltip) |
|---|---|---|
| Task | Task | یک کار مشخص با معیار Done |
| Agent | Agent | یک نقش در تیم (نه یک مدل) |
| Account profile | پروفایل اکانت | برچسب محلی که خودتان تعریف کرده‌اید؛ بدون رمز |
| Chat binding | اتصال چت | یادداشت دستی که این نقش در کدام چت کار می‌کند |
| Attempt | تلاش | یک بار ارسال پرامپت برای Task |
| Handoff | بستهٔ تحویل | پرامپت آماده‌شده برای یک تلاش |
| Prompt ready | پرامپت آماده — ارسال نشده | Workbench چیزی ارسال نمی‌کند |
| Copied | کپی شد — ارسال نشده | کپی در کلیپ‌بورد به معنی ارسال نیست |
| You confirmed sending | ارسال را تأیید کردید | زمان تأیید شما ثبت شد |
| Answer received | پاسخ دریافت شد | پاسخی که Paste کردید ثبت شد |
| Partial answer | پاسخ ناقص | بعضی موارد خواسته‌شده نیامده |
| Repair | اصلاح پاسخ | پرامپت تکمیلی برای همان تلاش |
| Re-plan | برنامه‌ریزی دوباره | درخواست از مدیر پروژه |
| Context request | درخواست زمینه | مدل فایل/خطوط مشخصی خواسته |
| Evidence | شاهد | تست/Build/Git/تأیید شما |
| Needs attention | نیازمند توجه | مواردی که منتظر اقدام شما هستند |
| Deliveries | تحویل‌ها | Milestone، Version، Build و انتشار |
| Released (recorded by you) | منتشرشده (ثبت‌شده توسط شما) | منبع شاهد همیشه کنار وضعیت |

## ۵. ده جریان کار (نقاط تصمیم و مسیر خطا)

| F1 | اولین باز کردن و قدم بعدی | Overview → ردیف «قدم بعدی» با دکمهٔ فعل‌دار (مثلاً «بازبینی تحویل HO-0002») → نمای مربوط با انتخاب مورد | بدون Task: Empty state «هنوز Taskی نیست — برنامه‌ریزی پروژه» |

| F3 | تأیید ارسال و پاسخ | پنل پرامپت → «این پرامپت را ارسال کردم» (کنار متن) → نشان «ارسال را تأیید کردید» → Paste در پنل پاسخ → «بررسی و ثبت پاسخ» | پاسخ نامعتبر → Banner خطا با چهار بخش (§6.4) |

| F5 | قابلیت جدید | Inspector → «درخواست تغییر…» → **یک Dialog**: متن درخواست + سه گزینهٔ Radio با توضیح، گزینهٔ پیشنهادی انتخاب‌شده و دلیلش → «ادامه» | مبهم: هیچ گزینه پیش‌انتخاب نمی‌شود |
| F6 | Context Request | Paste پاسخ → تشخیص → Files & Context با درخواست ثبت‌شده در فهرست → «آماده‌سازی بستهٔ زمینه…» (ابزار موجود) | «آماده» ≠ «ارسال‌شده» در ستون وضعیت |
| F7 | Team Proposal | Banner در Overview/Team «پیشنهاد برای بازبینی» → Team › بخش بازبینی → انتخاب موارد → «پذیرش موارد انتخاب‌شده» / «رد همه» / «درخواست اصلاح» | Proposal کهنه: تأیید دوباره (موجود) |

| F9 | شاهد Build/Version | Deliveries → جدول Version با ستون «شاهد» → انتخاب → Inspector جزئیات commit/tag/URL | وضعیت بدون شاهد سبز نمی‌شود |
| F10 | فعالیت گذشته | Timeline → فیلتر نوع/متن → جملهٔ انسانی؛ منبع (workbench / user / legacy) در ستون جدا | legacy با برچسب «قدیمی/گزارش‌شده» |

## ۶. وابستگی‌ها (Scope §10.3)

هیچ‌کدام از جریان‌ها Action دامنه‌ای تازه نمی‌خواهد. داده‌های لازم برای نشان «آماده / کپی / تأییدشده» از `v2/workflow.task_stage` (موجود) خوانده می‌شود. فهرست Context Request از Inbox/attempts موجود خوانده می‌شود. اگر داده‌ای در Read Model نباشد، نمایش داده نمی‌شود (اختراع نمی‌شود).
